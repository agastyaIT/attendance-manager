# Deploy Attendance Manager to Render

This repository is configured as one FastAPI web service that serves the HTML/CSS/JavaScript frontend from `/app/` and the API from the same origin.

## Important: SQLite persistence

The included `render.yaml` attaches a 1 GB persistent disk at `/var/data` and stores SQLite at `/var/data/attendance.db`. The Blueprint uses Render's paid `starter` web-service plan because Render Free web services do not support persistent disks. Do not change this service to Free while relying on SQLite for real attendance records.

## 1. Push the project to GitHub

1. Create a new GitHub repository.
2. Upload the contents of this folder (not the ZIP itself).
3. Confirm `.env`, `.venv`, and database files are not committed.

## 2. Create the Render service

1. Open https://dashboard.render.com/ and choose **New + → Blueprint**.
2. Connect the GitHub repository containing `render.yaml`.
3. Review the service and disk configuration, then apply it.
4. Render installs dependencies and starts `backend.main:app`.

The Blueprint configures:

- Build: `pip install -r requirements.txt`
- Start: `uvicorn backend.main:app --host 0.0.0.0 --port $PORT`
- Health check: `/health`
- SQLite file: `/var/data/attendance.db`
- JWT secret: generated by Render

## 3. Create the first administrator

After the first successful deploy, temporarily add these environment variables in the Render service's **Environment** page:

- `BOOTSTRAP_ADMIN_NAME` — administrator's display name
- `BOOTSTRAP_ADMIN_EMAIL` — administrator's email
- `BOOTSTRAP_ADMIN_PASSWORD` — a unique password of at least 12 characters

Save the variables and let the service redeploy. Then open the service Shell and run:

```bash
python -m backend.bootstrap_admin
```

After the command reports success, remove all three `BOOTSTRAP_ADMIN_*` variables and save. Do not leave the initial password in service configuration. The bootstrap command refuses to create another administrator if one already exists.

## 4. Open the application

Open the service's `https://<your-service>.onrender.com/` URL. The root path redirects to `/app/index.html`. API documentation is at `/docs`; health status is at `/health`.

## Fresh database behavior

The source ZIP's existing database files and backups were intentionally excluded. On first startup, the app creates a new empty database and applies its schema migrations. You must create the first administrator and then add faculty, subjects/assignments, and students as appropriate.

## Notes

- The app uses same-origin API requests, so frontend and backend are served from one Render service.
- Keep the persistent disk mounted at `/var/data`; changing or removing it can make the database unavailable.
- Back up the SQLite database regularly. A persistent disk is not a substitute for backups.
- Render free web services have ephemeral filesystems and cannot attach persistent disks.
